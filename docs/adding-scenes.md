# Adding a new scene

How to ship another clip (video + audio + line refs) so it shows up in the app and grades correctly.

## What you need

Every scene is two things:

1. **S3 assets** — public files under `scenes/<scene_id>/`
2. **Postgres row** — one `scenes` row with URLs + `chunks` JSON (timings + grader refs)

There is no admin API. Scenes get into Postgres via **seed on API boot** or a **manual SQL insert**.

```text
Local media → S3 upload → seed JSON → API restart/redeploy → GET /api/v1/scenes
```

---

## 1. Pick an id and folder

Use a stable primary key, e.g. `scene_my_clip`.

S3 prefix will be:

```text
s3://voicely-proto-0821/scenes/scene_my_clip/
```

Copy the valorant layout as a template:

```text
my-scene/
  video.mp4              # master clip (embedded audio for playback)
  soundtrack.mp3       # background bed (prep + export mix)
  vocals.mp3             # full vocals (source for slicing refs)
  thumbnail.png
  chunks.json            # timings for ffmpeg + seed
  upload-to-s3.sh        # copy from valorant/upload-to-s3.sh
  refs/                  # generated by upload script
```

---

## 2. Author `chunks.json`

Same shape as [`valorant/chunks.json`](../valorant/chunks.json). One entry per line the user records.

```json
{
  "id": "scene_my_clip",
  "title": "My Clip",
  "chunks": [
    {
      "index": 0,
      "start_time_sec": 1.3,
      "end_time_sec": 3.0,
      "transcript": "Line one.",
      "reference_audio_url": "https://voicely-proto-0821.s3.amazonaws.com/scenes/scene_my_clip/refs/chunk_00.wav"
    }
  ]
}
```

Rules:

- `index` starts at `0`, contiguous (`0..n-1`).
- `start_time_sec` / `end_time_sec` match the **vocals** track (used for slicing + studio jumps).
- `reference_audio_url` must match the S3 key the upload script will write: `refs/chunk_XX.wav`.
- Chunk count must match the number of takes the user records in studio.

---

## 3. Upload to S3

Use your **personal AWS CLI** credentials (not the `voice-api` IAM user — that user is exports-only).

From your scene folder:

```bash
BUCKET=voicely-proto-0821 PREFIX=scenes/scene_my_clip ./upload-to-s3.sh
```

The script (see [`valorant/upload-to-s3.sh`](../valorant/upload-to-s3.sh)):

1. Slices `vocals.mp3` → `refs/chunk_XX.wav` using `chunks.json`
2. Uploads `video.mp4`, `soundtrack.mp3`, `vocals.mp3`, `thumbnail.png`, `refs/*`

Verify:

```bash
aws s3 ls s3://voicely-proto-0821/scenes/scene_my_clip/ --recursive
curl -I "https://voicely-proto-0821.s3.amazonaws.com/scenes/scene_my_clip/video.mp4"
```

`scenes/*` must be **public-read** (browser + grader fetch via HTTPS).

---

## 4. Add seed JSON

Create [`backend/internal/seed/scene_my_clip.json`](../backend/internal/seed/scene_my_clip.json) (copy [`scene_valorant.json`](../backend/internal/seed/scene_valorant.json)).

Required fields:

| Field | Notes |
|-------|--------|
| `id` | Same as S3 folder name, e.g. `scene_my_clip` |
| `title` | Shown in UI |
| `difficulty` | e.g. `Beginner`, `Intermediate`, `Advanced` |
| `thumbnail_url` | `.../scenes/<id>/thumbnail.png` |
| `video_url` | `.../video.mp4` |
| `soundtrack_url` | `.../soundtrack.mp3` |
| `vocals_url` | `.../vocals.mp3` (kept for pipeline; studio uses video audio) |
| `chunks` | Full array with `reference_audio_url` per line |

URL base (current bucket):

```text
https://voicely-proto-0821.s3.amazonaws.com/scenes/<scene_id>/<file>
```

### Wire seed into Go

Today [`backend/internal/seed/seed.go`](../backend/internal/seed/seed.go) only embeds **one** file. For a new scene, extend it to upsert each JSON file (same `OnConflict` on `id`):

```go
//go:embed scene_valorant.json scene_my_clip.json
var sceneFiles embed.FS

// loop: ReadFile → Unmarshal → gdb.Clauses(OnConflict...).Create(&scene)
```

Until you add that, a new JSON file alone will **not** load — you must update `seed.go` or use SQL (below).

Seed **upserts** by `id`: redeploying the API updates title, URLs, and chunks for existing ids; it does not delete old scenes.

---

## 5. Load into Postgres

### Option A — Redeploy API (recommended)

Prod already has `DATABASE_URL` on Render. Push seed JSON + `seed.go` change → **Manual Deploy** on `voicely-api`. Seed runs on every boot.

### Option B — Run API locally against prod DB (quick one-off)

```bash
cd backend
export DATABASE_URL="postgresql://...supabase...?sslmode=require"
go run ./cmd/api
# wait for log: seeded scene "scene_my_clip"
# Ctrl+C
```

Use carefully — you are writing to production. Double-check the connection string.

### Option C — Supabase SQL editor

Insert directly into `scenes` (`chunks` column is **jsonb**). Match the seed JSON shape. No redeploy needed; harder to maintain.

## 6. Verify

```bash
# List scenes
curl -s https://YOUR-API.onrender.com/api/v1/scenes | jq

# One scene
curl -s https://YOUR-API.onrender.com/api/v1/scenes/scene_my_clip | jq

# Thumbnail + video reachable
curl -I "https://voicely-proto-0821.s3.amazonaws.com/scenes/scene_my_clip/thumbnail.png"
```

In the app: **Scenes** carousel → open scene → prep → record → grade → export.

---

## Checklist

- [ ] Unique `scene_id`
- [ ] `chunks.json` timings match vocals/video
- [ ] S3 upload complete (`video`, `soundtrack`, `vocals`, `thumbnail`, `refs/*`)
- [ ] Seed JSON URLs match S3 keys
- [ ] `seed.go` embeds new JSON (or SQL insert done)
- [ ] API redeployed or one-off seed run
- [ ] `GET /api/v1/scenes` shows the new scene
- [ ] End-to-end grade works (refs URLs return 200)

---

## Updating an existing scene

Change timings or copy → update `chunks.json` → re-run upload (overwrites S3 refs) → update seed JSON → redeploy API. Same `id` = upsert overwrites the row.
